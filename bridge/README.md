# Amadeus bridges

Trustless: each chain verifies Amadeus consensus (BLS12-381 via the EIP-2537 precompiles),
Amadeus verifies each chain's finality (node: `ex/native/rdb/src/consensus/bridge/<chain>`,
BIC `ex/native/rdb/src/consensus/bic/bridge.rs`). Recipients claim themselves, or pay a relay its
cost (`gasDropFee`, out of the order), which delivers and funds their gas (`gasDrop`). See AGENTS.md.

Amadeus is the hub: an order from one chain to another (BSC -> Base) is proven on Amadeus and passed
on as an Amadeus order, the AMA staying in escrow; the user only acts on the source chain.
At most 10M AMA is outside Amadeus at once (the escrow): whatever goes wrong on a remote chain, no
more can be lost. Coins coming back to Amadeus free room; moves between chains never left the escrow,
so they do not count. Amadeus also keeps how much of the escrow backs each chain's wAMA, so coins only
ever leave a chain out of that chain's own backing. The bridge is **feeless**: users pay only the
delivery (the relay's gas, at cost) or claim themselves. Each side's admin may set a fee, taken off the
source asset at the source (Amadeus `Bridge.set_fee`, burned; EVM `setFee`, to the admin, on moves
between chains; parts per million, at most 1%; orders already made keep theirs), and pauses its own
side (`pause`). An EVM admin hands over in two steps (`transferAdmin`, then `acceptAdmin` by the new
one); the Amadeus admin is a BIC constant (`bridge.rs` ADMIN, set before the mainnet bridge fork: a test
fails while it, the BSC contract, wAMA or trust header are placeholders). Run the bridge tests locally
before a release: `forge test` (bridge/evm), `npm test` (bridge/relayer), `cargo test --release --
tests::bridge tests::eth tests::arb tests::polygon` (ex/native/rdb).

## Contracts (`evm/src/`)
- `AmadeusLightClient.sol`: stores the state root of every Amadeus claim signed by ≥ 67% of
  the active validators it knows; adopts validator-set changes from the proven validator
  record `bic:epoch:validators:height:<h+1>`.
- `AmaBridge.sol`: `send` burns wAMA and records `orders[nonce] = keccak256(order)` in
  storage slot 0 (which Amadeus proves); `receiveOrder` mints wAMA for a proven Amadeus
  order (`receiveOrderWithConsensus` also submits the consensus, one tx). No fee unless the admin sets
  one (`setFee`, charged only on sends to another chain, to the admin). Tips are minted to the deliverer, `msg.value`
  (the gas drop, at most 30k gas for the transfer) goes to the recipient. 10M AMA cap per day per
  direction on the contract, admin can only pause. `send` takes a destination: Amadeus, or another
  chain through Amadeus (its wAMA and a 20-byte recipient).
- `WAMA.sol`: wrapped AMA, 9 decimals, minted/burned by the bridge only.
- `Bls12381.sol`, `Hbsmt.sol`, `Order.sol`: BLS hash-to-curve + pairing, Amadeus state-tree
  proofs, the shared packed order format (`ex/native/rdb/src/consensus/bridge/order.rs`).
- `Constants.sol`: generated by `gen_constants.py`.

### Build / test (in `evm/`)
```
forge install foundry-rs/forge-std   # lib/ is not committed
forge test -vv
```
Test vectors (`test/vectors/amadeus.json`) are produced by the node itself:
```
cd ../../ex/native/rdb && cargo test --release bridge_vectors_gen -- --ignored
```

### Deploy (in `evm/`, e.g. BSC testnet)
```
cp ../.env.example ../.env   # then fill in the keys
set -a; . ../.env; set +a
forge script script/Deploy.s.sol --rpc-url bsc_testnet --broadcast --with-gas-price 100000000 --priority-gas-price 100000000
```
(BSC's base fee is 0, so without a gas price forge offers 1 wei and the deploy never mines.)
Then put the addresses in `relayer/src/networks.js`, and the trust epoch header and addresses in
the Amadeus BIC (`bridge.rs`). Replacing only wAMA + bridge: `LIGHT_CLIENT=<lc>` (Amadeus keeps received
markers per bridge contract, so a new contract starts its nonces fresh; retire the old one first:
pause it once no wAMA of it is left and no order is in flight). Trust points: `cd relayer && npm run init-trust`.

## Relay (`relayer/`)
Idle unless needed: delivers tipped orders (`minTip`), adopts new Amadeus validator records on
each chain's light client, and keeps Amadeus' light clients of the chains in reach.
BSC: a vote verifies against the stored set, or catches up over many epochs when >= 2/3 of the
stored set signed and every signer key is one Amadeus already adopted, so the relay submits only
epoch blocks that bring a new vote key, plus one every ~16k blocks. It also teaches Amadeus
every vote key BSC's StakeHub registered (`Bridge.vote_key`, a storage proof: StakeHub only takes
keys with a proof of possession), hourly, so keys are known before they first sign.
If fast finality can no longer vouch for the next set (over 1/3 of the stored set stopped voting
and BSC replaced them), `Bridge.seal_update` adopts it from headers sealed by more than half of
the stored set, the rule BSC itself falls back to; it adopts the set only, never a root. A set vouches for votes from
its epoch block to 128k blocks past it. Nothing depends on time: one epoch past the stored set
always fits, so after any pause the relay steps forward again. Kept current, the votes Amadeus
takes stay inside BSC's slashing window (`felonySlashScope`, 192k blocks; a governance value,
recheck before mainnet); the log and `/status` raise an ALERT once the stored set is 32k blocks
behind the head. One key per network covers every chain: the EVM key, with the Amadeus key derived
from it (`core.js amadeusSeedFromRelayKey`).
- `npm run relay`: local Node loop (`NETWORK`, default testnet; key `PRIVATE_KEY` from `../.env`;
  cursors in `state-<network>.json`).
- Cloudflare worker (`worker/`, `wrangler.jsonc`): one Worker for every network, picked by
  hostname: https://mainnet-bridge.ama.one, https://testnet-bridge.ama.one. Each network has its
  own Durable Object, which queues deliveries and sends every transaction from its alarm. It
  serves the frontend, `POST /deliver` and `GET /status`. Secrets `MAINNET_PRIVATE_KEY`,
  `TESTNET_PRIVATE_KEY`. `npm run dev` runs it locally on testnet (secrets in `.dev.vars`).
- Run only one relay per network: two would race on the same keys.

## Frontend (`relayer/frontend/`)
`index.html` + `app.js`, bundled by Vite (`npm run build`, run by wrangler before every deploy
and dev) into `relayer/public/`. The worker writes the network's settings (its live chains) into
the page's `#config` script as it serves it; the page has a chain picker.

## Adding a chain
EVM chain: deploy `evm/` there, add it to `relayer/src/networks.js`, write
`relayer/src/chains/<finality>.js` (`rootArgs(h)`, `sync(upTo)`, `trust()`), and the matching light client plus
route in the node (`consensus/bridge/<chain>`, `bic/bridge.rs`).

## Notes
- Public RPCs only serve `eth_getProof` at the head block. Orders never change once
  written, so the relay proves at head h right away and submits once h is finalized.
- Gas (forge): receiveOrderWithConsensus ~750k (7 signers), receiveOrder ~350k,
  submitValidatorSet ~420k, send ~120k.
