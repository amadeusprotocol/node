# Amadeus ⇄ BSC bridge (BSC side)

Trustless: BSC verifies Amadeus consensus (BLS12-381 via the EIP-2537 precompiles),
Amadeus verifies BSC fast finality (`ex/native/rdb/src/consensus/bridge/bsc`, BIC
`ex/native/rdb/src/consensus/bic/bridge.rs`). Recipients claim themselves, or tip a relay
(`gasDropFee`, out of the order) which delivers and funds their gas (`gasDrop`). See AGENTS.md.

## Contracts (`src/`)
- `AmadeusLightClient.sol`: stores the state root of every Amadeus claim signed by ≥ 67% of
  the active validators it knows; adopts validator-set changes from the proven validator
  record `bic:epoch:validators:height:<h+1>`.
- `AmaBridge.sol`: `send` burns wAMA and records `orders[nonce] = keccak256(order)` in
  storage slot 0 (which Amadeus proves); `receiveOrder` mints wAMA for a proven Amadeus
  order (`receiveOrderWithConsensus` also submits the consensus, one tx). The 0.1 bp fee is only
  charged (and burned) on Amadeus sends; none here. Tips are minted to the deliverer, `msg.value`
  (the gas drop) goes to the recipient. 10M AMA cap per day per direction, admin can only pause.
- `WAMA.sol`: wrapped AMA, 9 decimals, minted/burned by the bridge only.
- `Bls12381.sol`, `Hbsmt.sol`, `Order.sol`: BLS hash-to-curve + pairing, Amadeus state-tree
  proofs, the shared packed order format (`ex/native/rdb/src/consensus/bridge/order.rs`).
- `Constants.sol`: generated by `gen_constants.py`.

## Build / test
```
forge install foundry-rs/forge-std   # lib/ is not committed
forge test -vv
```
Test vectors (`test/vectors/amadeus.json`) are produced by the node itself:
```
cd ../../ex/native/rdb && cargo test --release bridge_vectors_gen -- --ignored
```

## Deploy (BSC testnet, Chapel, chain id 97)
```
cp .env.example .env    # testnet-only key funded from the faucet
forge script script/Deploy.s.sol --rpc-url bsc_testnet --broadcast
```
Then set the deployed bridge / wAMA addresses and the BSC trust epoch header in the
Amadeus BIC (`bridge.rs`). Replacing only wAMA + bridge: `LIGHT_CLIENT=<lc> LAST_NONCE=<old bridge nonce>`
(Amadeus already marked those nonces received).

## Relay (`relayer/`)
Idle unless needed: delivers tipped orders (`MIN_TIP`), adopts new Amadeus validator records on
the BSC light client, and keeps the Amadeus BSC light client in reach with one skipping update
when the trusted set's signers near quorum or half the 3M-block trust period has passed.
Logic in `src/core.js`; two ways to run it:
- `npm run relay`: local Node loop (env from `../.env`, cursors in `state.json`).
- Cloudflare worker (`worker/`, `wrangler.jsonc`): one Worker for both networks, picked by
  hostname: https://mainnet-bridge.ama.one, https://testnet-bridge.ama.one. Each network has its
  own Durable Object, which queues deliveries and sends every transaction from its alarm. It
  serves the frontend, `POST /deliver` and `GET /status`. Settings in `worker/networks.js`
  (Amadeus nodes mainnet-rpc.ama.one / testnet-rpc.ama.one); secrets `MAINNET_PRIVATE_KEY`, `TESTNET_PRIVATE_KEY`
  (BSC key; the relay's Amadeus key is derived from it).
  `npm run dev` runs it locally on testnet (secrets in `.dev.vars`).
  Run only one relay per network: two would race on the same wallets.

## Frontend (`relayer/frontend/`)
`index.html` + `app.js`, bundled by Vite (`npm run build`, run by wrangler before every deploy
and dev) into `relayer/public/`. The worker writes the network's settings into the page's
`#config` script as it serves it.

## Notes
- Public BSC RPCs only serve `eth_getProof` at the head block. Orders never change once
  written, so the relayer proves at head h right away and submits once h is finalized.
- Gas (forge): receiveOrderWithConsensus ~750k (7 signers), receiveOrder ~350k,
  submitValidatorSet ~420k, send ~120k.
